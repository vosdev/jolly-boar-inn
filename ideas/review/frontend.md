# Frontend review

I read CLAUDE.md, all of architecture.md, design.md, and every file under `client/src` apart from the tests, which I only skimmed for what they cover. I compared `lib/protocol.ts` with `ws/protocol.py` and each view's `data` fields with the server's `client_view`/`reveal`. They match field for field, and every difference is a documented choice for old servers. `svelte-check` passes with 0 errors. There is no `{@html}`, and player text only reaches the page through Svelte's escaped text. The bundle is small: 136 kB of JS, 36 kB of CSS and a 4 kB heads sprite. I did not run the app, so layout claims come from reading the CSS, not from screenshots. Findings that other reviewers already wrote up are listed at the end, not repeated.

## High

### FE-1. A room code typed with a space does nothing, and says nothing
- **Where:** [client/src/lib/session.ts:37](../../client/src/lib/session.ts#L37), [client/src/routes/Home.svelte:21](../../client/src/routes/Home.svelte#L21), [client/src/App.svelte:39](../../client/src/App.svelte#L39)
- **Problem:** `normalizeCode` only trims the ends and upper-cases. Codes are joined-up words (`ABYSSALBLUDGEON`, `AHRIMSSTAFF`), and the host reads them out as two words. A player who types "Abyssal Bludgeon", "abyssal-bludgeon" or "Ahrim's Staff" presses Join. `navigate('/r/ABYSSAL BLUDGEON')` pushes a path that `ROOM_PATH` (`[A-Za-z0-9]{1,32}`) does not match, so `resolve` returns `home`. Home is still the component on screen, so it is not reset. Nothing changes except the address bar, and no error appears.
- **Why it matters:** Typing the code is the way in for everyone who did not get the link. design.md §5.1.2 wants codes that are "shoutable" across a noisy table. A shouted code gets typed with a space, and to the player the Join button looks broken. Phone keyboards also like to add a space after a word.
- **Fix:** Make `normalizeCode` drop everything that is not a letter or a digit (`replace(/[^A-Za-z0-9]/g, '')`) and upper-case the rest. If the result is still not a valid code, Home should say "That is not a room code" instead of navigating. Add a test for `'abyssal bludgeon' → ABYSSALBLUDGEON`.

## Medium

### FE-2. Promote is a small one-tap button next to Kick, cannot be undone, and does not ask first
- **Where:** [client/src/components/Lobby.svelte:162](../../client/src/components/Lobby.svelte#L162), [client/src/app.css:408](../../client/src/app.css#L408)
- **Problem:** Each player row gives the host two `button.small` controls side by side, each about 32 px tall: Promote and Kick. Kick asks for confirmation (`confirm`). Promote sends at once. On the server there is no demote, and an admin cannot be kicked (SEC-11, by design).
- **Why it matters:** One slip of the thumb on a phone makes a player a permanent co-host. That player can then skip questions, end the game for everyone, or delete the room, and nobody can take it back. The two buttons sit next to each other and are below the 44 px tap size, so this mistake is easy to make.
- **Fix:** Ask first ("Make X a host? This cannot be undone."). Put Promote and Kick behind one small per-player menu, or at least make them 44 px tall with space between them. The wording of that confirmation is something players see, so the owner decides it.

### FE-3. The host's player list is wider than a phone screen
- **Where:** [client/src/components/Lobby.svelte:149](../../client/src/components/Lobby.svelte#L149), [app.css:468](../../client/src/app.css#L468), [app.css:492](../../client/src/app.css#L492)
- **Problem:** Each row in `ul.players li` is a flex row that never wraps: a dot, a 32 px head, `.name` (at least `6rem`, 96 px), a "✓ ready" tag, Promote and Kick, with 0.6rem gaps. From the CSS, the smallest this row can be for a player who is ready is about 365 px. A panel on a 375 px phone has about 301 px inside it, and a 360 px Android has about 286 px. Nothing clips the row, so the whole page gets wider than the screen. A long name with no spaces also spills over the buttons, because `.name` has no `overflow-wrap`.
- **Why it matters:** The host runs the lobby from a phone, and in the lobby everyone is asked to tap ready. So every ready player's row pushes the page sideways, and the host has to pan left and right to reach Start. D2 and D9 hold other screens to "no horizontal scroll", but this one has no such check.
- **Fix:** Let the row wrap (`flex-wrap: wrap`) so the admin buttons drop onto a second line on a narrow screen. Give `.name` `min-width: 0; overflow-wrap: anywhere`. Add a 320/375 px check of the lobby as host to the next D-task that touches it.

### FE-4. Nothing tells keyboard or screen-reader players that the screen changed
- **Where:** [client/src/components/PointsSlot.svelte:64](../../client/src/components/PointsSlot.svelte#L64), [client/src/routes/Room.svelte:327](../../client/src/routes/Room.svelte#L327), [client/src/components/questions/Question.svelte:52](../../client/src/components/questions/Question.svelte#L52), [GemChoices.svelte:61](../../client/src/components/questions/GemChoices.svelte#L61), [Room.svelte:258](../../client/src/routes/Room.svelte#L258), [client/index.html:6](../../client/index.html#L6)
- **Problem:** The code never moves focus after a new question, a reveal or standings. A screen reader announces changes only inside a "live region", an area it watches for new text, and no such area announces them. The first answer you press becomes `disabled` or is swapped out by the `{#key}`, so keyboard focus falls back to `<body>`. The next question then starts back at the top bar. The verdict box (`PointsSlot`, `role="status"`) is inserted together with its text. Screen readers often stay silent for a live region that appears already filled, so "Right, +850" is often never read. The "Connection lost" banner has no role, and the page title never changes.
- **Why it matters:** A blind player hears nothing when a 10-second question opens, has to hunt for the answers, and may never hear whether they were right. A keyboard player has to Tab past the skip link, sign, name chip and theme button on every question. D8 asks that answers be "reachable and operable by keyboard". They are reachable, but not in time.
- **Fix:** Keep one live region mounted in `Room` for the whole game (`aria-live="polite"`, never removed), and write into it "Question 3 of 10", the verdict sentence, and "Connection lost". On `question_open`, move focus to the question's heading or its first answer. Add `role="status"` to the reconnect banner. Set `document.title` per screen.

### FE-5. `Room.svelte` draws every screen, and the planned stage work will make it worse
- **Where:** [client/src/routes/Room.svelte:243](../../client/src/routes/Room.svelte#L243), [Room.svelte:346](../../client/src/routes/Room.svelte#L346), [Room.svelte:380](../../client/src/routes/Room.svelte#L380), [Room.svelte:292](../../client/src/routes/Room.svelte#L292), [Room.svelte:336](../../client/src/routes/Room.svelte#L336), [Lobby.svelte:88](../../client/src/components/Lobby.svelte#L88)
- **Problem:** One 511-line component owns the socket's lifecycle, the goodbye screen, the lobby, the final screen, the splash, standings, the open question, the waiting state, the reveal and the host panel. It also feeds the global timer bar from an `$effect`. The choice "`RandomEvent` or `Question`" is written out twice, once for the open question and once for the reveal, with the props copied. The error banner appears three times (twice here, once in `Lobby`).
- **Why it matters:** D13 puts both the open question and the reveal on the stage. D16 animates the handover between the host and the event NPC across those same two branches. New phases, like `standings` in D9, add more `{:else if}`. Each of these changes has to be made twice and kept in step, inside the file that also holds the connection code. That is where a change meant for the reveal quietly breaks the open question.
- **Fix:** Before D13, move the question area into one `QuestionStage` component. Give it the question, `reveal` or null, your answer and your result, and let it choose the event card or the plain question once. Make the banner an `ErrorBanner` component. Room then keeps only the socket and the choice of screen.

### FE-6. A rename that gets no reply locks the name editor until the page is reloaded
- **Where:** [client/src/components/IdentityChip.svelte:49](../../client/src/components/IdentityChip.svelte#L49), [IdentityChip.svelte:75](../../client/src/components/IdentityChip.svelte#L75), [IdentityChip.svelte:104](../../client/src/components/IdentityChip.svelte#L104), [client/src/lib/stores.ts:73](../../client/src/lib/stores.ts#L73)
- **Problem:** After `set_profile` is sent, `pending` is cleared in only two cases: a `room_updated` that shows the new name, or an error whose code is in `PROFILE_ERRORS`. It stays set when the frame goes into a socket that died silently (RT-1), when the server replies `bad_state` (which lands in `lastError`), or when the room ends before the reply. Nothing times it out, and opening and closing the popover does not reset it. The chip lives in `App`, so it outlives the room. `submit` and "New head" both return early while `pending` is set.
- **Why it matters:** The player sees "Asking the room…" forever. Save and New head stay greyed out in the room, and also on Home and in the next room, until a reload. The player has no way to guess that a reload is the fix.
- **Fix:** Clear `pending` on any `welcome`, on leaving the room (`live` becoming null), on any `error` that arrives after the send, and after a timeout of a few seconds. Add a test that sends and gets no reply.

### FE-7. The connection code and the state it produces have no unit tests
- **Where:** [client/src/lib/ws.ts:76](../../client/src/lib/ws.ts#L76), [client/src/lib/stores.ts:158](../../client/src/lib/stores.ts#L158), [client/src/components/Lobby.svelte:1](../../client/src/components/Lobby.svelte#L1), [client/src/routes/Join.svelte:1](../../client/src/routes/Join.svelte#L1), [client/src/components/IdentityChip.svelte:1](../../client/src/components/IdentityChip.svelte#L1)
- **Problem:** No test file covers `RoomSocket`: the backoff, which close codes end the connection for good, ping and pong, the reconnect when the tab comes back into view. `applyServerMessage` is exercised only through a handful of Room tests. The Lobby's Start gate, the Splash's single take-back, Join's automatic re-roll of the name on `name_taken`, and the chip's save flow have no tests at all.
- **Why it matters:** These are the parts that run when a phone locks, a name clashes, or the host starts early, which is exactly where manual runs miss things. RT-1's fix and FE-6's fix both change this code, and at the moment nothing would catch a regression.
- **Fix:** Add `ws.test.ts` using a fake `WebSocket` and fake timers. Add `stores.test.ts` as a table of frames in and store values out. Add one component test each for Lobby, Join and IdentityChip. RT-1 already sketches the first test.

## Low
- FE-8 [stores.ts:244](../../client/src/lib/stores.ts#L244) — An answer that just misses the close gets `not_open`. A red banner then shows the server's own wording ("no question is open") and stays through every following question until the player taps "dismiss". Clear `lastError` on `question_open` and show player-facing text keyed on `code`.
- FE-9 [Splash.svelte:86](../../client/src/components/Splash.svelte#L86) — `span`, the full length of the countdown bar, is set in an `$effect` (code that runs after the screen is drawn), when it could be a `$derived` value. So the countdown bar is drawn empty for one frame, then jumps. The effect also re-runs on every `pong` because it reads `$serverOffsetMs`, which refills the bar in the middle of the countdown.
- FE-10 [Join.svelte:68](../../client/src/routes/Join.svelte#L68) — Join is a sequence of steps driven by two `$effect`s that each write a value they also read (`$profile`, `attempted`). It works today, but the next person to edit it can easily make it loop or join twice. A plain async function called after `getRoom` would say the same thing.
- FE-11 [MoreLess.svelte:112](../../client/src/components/questions/types/MoreLess.svelte#L112) — The two buttons are keyed by item name. A hand-written question that compares an item with itself (for example GE against high alch) produces duplicate keys, which Svelte's production build throws on. There is no `<svelte:boundary>` anywhere, so the whole room screen goes blank instead of showing the question. Key by index, and wrap the question area in a boundary that falls back to "this version cannot show it".
- FE-12 [MoreLess.svelte:24](../../client/src/components/questions/types/MoreLess.svelte#L24) — The docstring says the right answer "gets a ✓ and an `--ok` ring". D8 removed both, so the comment now describes the opposite of the code.
- FE-13 [Lobby.svelte:75](../../client/src/components/Lobby.svelte#L75) — "Start anyway", Kick and End game ([Room.svelte:436](../../client/src/routes/Room.svelte#L436)) depend on `window.confirm`. Some in-app browsers, the ones that open when you tap a link in a chat app, suppress it and return false, and your memory notes that the preview pane does too. There the button silently does nothing. A small in-page confirmation would work everywhere.
- FE-14 [CopyLink.svelte:25](../../client/src/components/CopyLink.svelte#L25) — The input's `id` is the label text, "Link for players", and an id with spaces is invalid HTML. [Lobby.svelte:98](../../client/src/components/Lobby.svelte#L98) has `<label for="join-link">`, which points at nothing. A screen reader reads both fields without a proper name.
- FE-15 [vocab.ts:61](../../client/src/lib/vocab.ts#L61) — On every keystroke `search` sorts with a comparison that re-folds both names, and focusing the box renders the whole list as `<li>` elements. That is fine for the 18 examines and 176 items. It will stutter on a phone with the planned `npcs` list of thousands. Fold each entry once when the list loads, and cap how many results are drawn.
- FE-16 [tsconfig.app.json:2](../../client/tsconfig.app.json#L2) — The app's TypeScript settings leave out `noUncheckedIndexedAccess` and `noUnused*`, which the node config has. So `MODES[id]` is typed as always present. Each view also casts `data as unknown as Data` to a shape declared only inside that component. A field renamed on the server is `undefined` at runtime, not a compile error.
- FE-17 [Home.svelte:111](../../client/src/routes/Home.svelte#L111) — "Rooms you created here" never drops rooms that expired. Codes come from 297 words and are reused after the 3-day TTL, so "Open" on an old entry can lead into a stranger's room through "Join again". Also, the comment at [Home.svelte:9](../../client/src/routes/Home.svelte#L9) says rooms last "thirty days".
- FE-18 [Room.svelte:427](../../client/src/routes/Room.svelte#L427) — The host button says "Skip to the next question" during the reveal of a round's last question, which goes to the standings, and of the game's last question, which goes to the final screen.
- FE-19 [Create.svelte:332](../../client/src/routes/Create.svelte#L332) — The reveal-length field is not range-checked the way the round fields are. Typing 45, or clearing it, enables Create and comes back as a raw server error.
- FE-20 [Timer.svelte:42](../../client/src/components/Timer.svelte#L42) — The clock logic (tick, offset, `visibilitychange`) is copied between `Timer` and `TimerBar`. The visually-hidden `.sr` CSS is copied three times ([GemButton.svelte:239](../../client/src/components/questions/GemButton.svelte#L239), [PointsSlot.svelte:138](../../client/src/components/PointsSlot.svelte#L138), [Scoreboard.svelte:361](../../client/src/components/Scoreboard.svelte#L361)). Move the clock into `lib/clock.ts` and `.sr` into `app.css`.

## Seen outside this area
Already reported by other reviewers, so not repeated above. What players would see:
- RT-1 (realtime): after a phone wakes on a connection that died silently, the screen stays frozen for up to 40 s with no "reconnecting" banner, and an answer tapped then is shown as sent but never arrives. FE-6 is a second effect of the same dead socket.
- RT-7 (realtime): a late `answer_ack` can put the previous question's speed badge on the next question's "Answer in" line.
- TM-2 (types-modes): a Price is Right question asked by an NPC or the host shows four prices and never says which item they are for.
- TM-4 (types-modes): the gem buttons can take one answer only, so "pick all that apply" needs this component reworked first.
- TM-6 / TM-20 (types-modes): the six answer views copy the same parts, and they have already drifted. Guess the Examine's reveal drops the `explanation`, and free text drops the `subject`.
- SEC-11 (security): promotion is permanent, which is what makes FE-2's mis-tap costly.
